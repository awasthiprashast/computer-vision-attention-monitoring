# Privacy and responsible use

This project estimates attention from a webcam, so it deals with sensitive subject matter. This page states
exactly what the software does with data.

## What is processed

| Data | Where it is handled | Stored? | Sent over the network? |
|---|---|---|---|
| Webcam frames | In memory on the student's computer, to find face landmarks | No | **No** |
| Face landmarks | In memory, to compute EAR and head direction | No | **No** |
| Attention score, EAR, yaw, pitch, roll | Computed on the student's computer | Yes (database) | Yes, once per interval |
| Student ID, session ID, timestamp | Set by the client | Yes (database) | Yes |
| PDF reports (per-student summaries) | Generated by the dashboard | Optional (S3 bucket) | Only if S3 upload is configured |

The live video window the client shows (with the face mesh drawn over it) stays on the student's screen.

## Student identifiers

`STUDENT_ID` is whatever the person running the client chooses. If you use real names or emails, the database
and the reports contain personal data. Prefer pseudonymous IDs, and delete rows when they are no longer needed.

## Consent and use

- Get informed consent before anyone runs the client: what is measured, how often, who can see the results, and
  how long they are kept.
- Follow your institution's policies and the privacy law that applies to you (for example GDPR or FERPA).
- Treat the output as a rough engagement signal. The scoring is a heuristic that has not been validated
  against any ground truth, and it can be affected by glasses, lighting, camera angle, eye shape, disability
  and cultural differences in gaze behaviour. **Do not use it for grading, discipline, hiring or other
  high-stakes decisions.**

## Security notes

- The backend accepts readings only with a valid `X-API-Key` when `API_KEY` is set. Always set it outside local
  development.
- The sample AWS deployment uses plain HTTP; add HTTPS before using it with real students.
- The dashboard has no login. Restrict network access to it or put an authentication layer in front.
