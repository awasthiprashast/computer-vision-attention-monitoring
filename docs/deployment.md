# Deployment guide

There are two ways to run the system: locally with Docker Compose (no cloud account needed) or on AWS with
Terraform.

## 1. Local (Docker Compose)

```bash
cp .env.example .env        # optional: change passwords / set API_KEY
docker compose up -d --build
python scripts/seed_demo_data.py    # synthetic data, no webcam needed
```

| Service   | URL                               |
|-----------|-----------------------------------|
| Dashboard | http://localhost:8501             |
| API docs  | http://localhost:8000/docs        |
| Postgres  | localhost:5433 (user `attention`) |

To send real data, run the client with a webcam:

```bash
cd client
pip install -r requirements.txt
API_URL=http://localhost:8000/attention python attention_client.py
```

Stop everything with `docker compose down` (add `-v` to delete the database volume).

## 2. AWS (Terraform)

### What gets created

```
Internet
   |  :8000 (API, X-API-Key)        :8501 (dashboard, your IP only)
   v
EC2 t3.micro (public subnet, Elastic IP) -- docker compose: backend + dashboard
   |  :5432, TLS                      \__ IAM role: read 2 SSM parameters, write reports to S3
   v
RDS PostgreSQL 16 (private subnets, not publicly accessible)

S3 bucket (private, encrypted)  <-- PDF reports
SSM Parameter Store             <-- database URL and API key (SecureString)
```

- The VPC has public subnets for the host and private subnets (no internet route) for the database, so no NAT
  gateway is needed.
- The database accepts connections only from the app security group.
- There is no SSH. Use Session Manager (`ssm_session_command` output).
- The instance requires IMDSv2, and its root volume is encrypted.
- Secrets are generated by Terraform and read by the instance at boot through its IAM role; they are not in
  user_data.

### Prerequisites

- An AWS account and credentials configured locally (`aws configure` or SSO).
- Terraform 1.5 or newer.
- The branch you deploy must contain `docker-compose.aws.yml` (the instance clones it from GitHub). Set
  `repo_branch` if it is not `main`.

### Deploy

```bash
cd infra/terraform
cp terraform.tfvars.example terraform.tfvars   # set dashboard_allowed_cidr to your IP/32
terraform init
terraform plan
terraform apply
```

The instance needs a few minutes after `apply` to install Docker and build the images. Follow progress with
`aws ssm start-session ...` then `sudo tail -f /var/log/attention-bootstrap.log`.

Point the client at the new backend:

```bash
export API_URL=$(terraform output -raw api_url)
export API_KEY=$(terraform output -raw api_key)
python ../../client/attention_client.py
```

### Tear down

```bash
terraform destroy
```

This removes everything, including the database and the reports bucket. Set `skip_final_snapshot = false` first
if you want a last RDS snapshot (it is then yours to delete).

### Cost

Roughly 1 USD per day while running (t3.micro, db.t3.micro, one public IPv4 address, 20 GB volumes). Check the
AWS pricing calculator for your region, and run `terraform destroy` when you are done. The new-account free
plan may cover some of it.

### Known limitations

- **No HTTPS.** Traffic to port 8000 is plain HTTP, and the API key travels in clear text. For anything beyond a
  demo, put CloudFront or an Application Load Balancer with an ACM certificate in front.
- **The dashboard has no login**, so it is limited to one CIDR. A password-protected or SSO front end would be
  the next step.
- **Terraform state contains the generated passwords.** The default local state file is gitignored; for shared
  use, configure an encrypted S3 backend with state locking.
- **Single instance, single AZ database.** This is a demo topology, not a high-availability one.
- **Not applied in CI.** The workflow checks formatting and validity only; `plan` and `apply` need credentials.
